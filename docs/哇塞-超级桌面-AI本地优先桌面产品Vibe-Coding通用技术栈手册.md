# AI 本地优先桌面产品 Vibe Coding 通用技术栈手册

> 项目适配名称：哇塞-超级桌面——无限知识画布  
> 文档版本：V0.1（待产品确认）  
> 文档性质：技术决策、工程边界与验收手册，不是开发实现  
> 适用对象：产品经理、AI 产品经理、设计师、Vibe Coding 执行者、前端/桌面端开发者、代码型 AI Agent  
> 适用范围：Electron + React + TypeScript 的本地优先 AI 桌面应用；可作为同类“本地文件 + 知识库 + AI 工作台”项目的通用基线  
> 主要输入：《无限画布+项目管理-PRD》与《AI Agent 产品 Vibe Coding 通用前端技术栈手册》

## 0. 先说结论：本项目应怎样使用这份手册

本项目不是普通 Web MVP，而是一个需要访问本地文件、系统文件对话框、系统废纸篓、安全密钥存储和本地数据库的桌面应用。因此：

- 保留原通用前端手册中的 TypeScript strict、状态分层、安全、异常恢复、测试和真实验收原则；
- 不采用 Next.js 作为默认应用框架，继续使用 Electron + React + Vite；
- 不把“后端”简单理解成远程服务，Electron Main 进程中的本地服务层同样是业务事实来源；
- 不把 Local Storage 当成资料、索引或磁盘操作结果的最终事实来源；
- 不按移动 Web 的 390px 规则验收，改为桌面窗口尺寸、缩放、键鼠、操作系统和大画布性能验收；
- 不把 AI 对话当成唯一主流程，产品主闭环是“资料 → 索引 → 关系 → 检索 → 引用答案 → 结论 → 任务”。

正式开发前，AI 应依次输出并等待产品确认：

1. 《技术适配声明》；
2. 《本阶段开发文档》；
3. 受影响的数据结构、IPC 接口和迁移说明；
4. 可操作的验收路径。

未经确认，不开始重构、升级大版本、修改数据库结构或实现新功能。

## 1. PRD 功能点总览

### 1.1 产品主闭环

```text
导入本地资料
  → 本地解析和索引
  → 在无限画布上组织节点与关系
  → 按全画布或节点关系限定检索范围
  → AI 基于证据生成带引用回答
  → 保存为结论节点
  → 关联或转化为任务
```

### 1.2 功能域地图

| 功能域 | 核心能力 | 关键用户价值 |
|---|---|---|
| 无限画布 | 缩放、平移、框选、迷你地图、主题、布局整理 | 把资料和思考过程空间化 |
| 节点系统 | 文件、文件夹、知识库、AI、结论、任务、注释 7 类节点 | 用统一对象承载资料、分析和行动 |
| 关系系统 | relation、ai-context、workflow、visual 4 类连线 | 明确资料归属、AI 上下文和工作流关系 |
| 资料导入 | 对话框导入、系统拖放、文件夹递归扫描 | 低门槛接入本地资料 |
| 文档解析 | PDF、DOCX、Markdown、TXT、HTML | 把本地文件转为可检索文本 |
| 本地索引 | 分块、SQLite、FTS5、中文 bigram、覆盖检索 | 离线完成快速证据检索 |
| 知识库 | 拖入建关系、多选创建、真实来源统计 | 汇聚多个资料来源 |
| AI 资料问答 | 全局提问、节点级提问、证据引用、无 Key 降级 | 生成可追溯而非无依据的回答 |
| AI 快问 | 独立多轮通用对话，不读取画布资料 | 提供与资料问答隔离的通用助手 |
| 结论沉淀 | 回答保存为结论节点、保留引用 | 让分析结果可复用和追溯 |
| 任务管理 | 新建、编辑、列表、定位任务节点 | 从知识结论进入行动阶段 |
| 文件夹画布 | 收纳、子画布编排、批量重命名、移出 | 降低主画布复杂度 |
| 侧栏与检查器 | 资料、知识、任务、搜索、状态、设置、节点属性 | 提供结构化导航和编辑入口 |
| 文件系统操作 | 打开、定位、复制、重命名、重扫、移到废纸篓 | 打通画布与真实文件系统 |
| 持久化与恢复 | localStorage + SQLite、启动恢复、撤销 | 保留用户工作现场 |
| AI 配置 | 多供应商、模型、Base URL、系统指令、密钥加密 | 支持可配置的模型接入 |

### 1.3 画布交互能力

- 视口缩放范围 0.2x–2x，支持滚轮缩放、空格拖动画布、框选和边缘自动平移；
- 深色/浅色主题、点状网格、缩放控件和迷你地图；
- 节点拖动、缩放、重命名、复制粘贴、删除和搜索命中高亮；
- 连接点、宽松连线、连线重连、语义切换和连线中插入 AI 节点；
- 未连接节点整理、当前视图适配、所选节点水平整理；
- 最多 80 步撤销，当前 PRD 没有重做栈。

### 1.4 资料与文件操作能力

- 文件和文件夹混合多选导入；
- 从操作系统拖放文件到应用；
- 文件夹递归扫描、进度通知、子项展开；
- 支持 PDF、DOCX、Markdown、TXT 和 HTML，其他格式明确标为不支持；
- 打开原文件、Finder 中显示、复制到桌面、磁盘同步重命名、重新扫描；
- “移出画布”与“移到系统废纸篓”严格分离，真实删除必须二次确认。

### 1.5 检索与引用能力

- 文本清洗后按约 900 字符分块，重叠 120 字符；
- 支持英文词项和中文 bigram；
- 文件名命中权重高于正文；
- 普通检索返回前 5 条，覆盖模式最多覆盖 8 个来源；
- 引用包含文件、绝对路径、页码/标题定位、原文块和分数；
- 检索范围可来自全画布、所选节点或 AI 节点上游图关系。

### 1.6 AI 能力

- 支持 OpenAI、DeepSeek 和其他 OpenAI 兼容服务；
- API Key 在 Main 进程中使用系统 safeStorage 加密，Renderer 只看到脱敏提示；
- 全局资料问答只发送问题和检索证据，不发送完整文件；
- AI 节点拥有独立资料范围和独立系统指令；
- 回答以 Markdown 展示并带可点击引用；
- 未配置 Key 时降级为证据展示；
- AI 快问与画布资料问答隔离，保留最近多轮上下文。

### 1.7 当前“项目管理”能力的真实边界

PRD 标题包含“项目管理”，但当前规格中的项目管理主要是：

- 任务节点；
- 任务内容编辑；
- 任务侧栏列表与画布定位；
- 资料、知识、结论和任务之间的关系表达。

当前没有明确包含：多项目/多工作区、任务负责人、截止时间、优先级、看板、日历、提醒、依赖、团队协作、权限、项目统计。不能仅凭标题默认实现这些能力。

### 1.8 需求状态分层

| 状态 | 内容 |
|---|---|
| PRD 标注已实现 | v0.2.0 中的画布、7 类节点、4 类连线、本地导入与索引、关键词检索、引用问答、文件夹画布、侧栏、AI 设置等 |
| PRD 标注下一阶段 | 本地嵌入式向量检索；应用内 PDF/Word 预览与原文高亮 |
| 拆解者建议，不等于已确认需求 | 多项目/多工作区、节点协作与导出、定时提醒、移动端只读 |
| 已知缺口/风险 | 无 Redo、大文件夹全量重建、最近 300 chunk 可能漏检、node:sqlite 兼容、单工作区 |

## 2. 技术适配声明

### 2.1 项目判断

- 产品类型：本地优先的 AI 知识管理与无限画布桌面应用；
- 主要用户：研究者、分析师、产品经理、顾问、个人知识管理者和小团队负责人；
- 主要终端：macOS 桌面优先，兼容 Windows/Linux；
- 工程状态：PRD 声明已有 v0.2.0 源码，但当前工作目录只有 PRD，尚未读取实际源码与依赖锁文件；
- 当前任务：完成需求分析与技术手册，不开发产品。

### 2.2 推荐技术基线

在没有实际源码和锁文件验证前，沿用 PRD 中已经证明可工作的组合，不主动升级大版本：

| 层级 | 推荐方案 | 决策说明 |
|---|---|---|
| 桌面容器 | Electron 43（以现有锁文件为准） | 需要本地文件、系统能力、safeStorage 和跨平台桌面打包 |
| UI | React 18 + TypeScript 5.7 strict | 与现有项目兼容，严格类型作为底线 |
| 构建 | Vite 6 | 适合 Renderer 开发与构建，不引入不必要的 Next.js |
| 无限画布 | @xyflow/react 12.8 | PRD 已围绕 React Flow 建立完整交互模型 |
| 客户端状态 | Zustand 5 | 适合高频画布状态、选择状态与撤销快照 |
| 本地数据库 | Electron 内置 node:sqlite + SQLite WAL + FTS5 | 存资产、分块、索引和权威工作区快照 |
| 文档解析 | pdfjs-dist、mammoth、原生文本解析器 | 覆盖 PRD 已定义格式 |
| AI 接入 | openai SDK + 供应商适配层 | 隔离 Responses 与 Chat Completions 协议差异 |
| 图标 | lucide-react | 保持图标语言统一 |
| 单元/组件测试 | Vitest + React Testing Library | 覆盖状态、图操作和 UI 交互 |
| Main 进程测试 | node:test | 测索引、文件操作和数据库服务 |
| 桌面 E2E | Playwright Electron | 覆盖真实窗口、IPC 和核心闭环 |
| 代码质量 | ESLint + TypeScript + 构建检查 | 每阶段交付门槛 |

版本号是现状基线，不是永久锁定建议。开始开发前必须读取 `package.json` 和锁文件，再记录真实版本；同一阶段不做无关的大版本升级。

### 2.3 相对 Web 通用手册的主要偏离

| Web 默认项 | 本项目方案 | 原因 |
|---|---|---|
| Next.js App Router | Electron + Vite + React | 产品依赖桌面系统与本地文件能力 |
| 浏览器后端为唯一事实来源 | Main 本地服务层 + SQLite + 文件系统为事实来源 | 本项目多数业务在本机完成 |
| URL 保存任务/页面状态 | 工作区 ID、节点 ID、持久化视口和应用内导航状态 | Electron 单窗口工作台不依赖 Web URL 分享 |
| 移动端 390/768 验收 | 960×640 最小窗口、1440×900 默认窗口及高分屏验收 | 当前是桌面产品，移动端不在已实现范围 |
| SSE/WebSocket 长任务 | IPC 事件 + 可取消的本地任务；远程 AI 可使用 SDK 流或普通请求 | 索引发生在 Main，Renderer 通过 IPC 订阅进度 |
| HttpOnly Cookie 鉴权 | safeStorage + Main 进程密钥访问 | 当前没有账号系统，模型密钥不得进入 Renderer |
| Next.js 部署 | Electron 打包、签名、公证、自动更新策略 | 桌面软件交付方式不同 |

## 3. 工程架构与信任边界

### 3.1 三层进程架构

```text
Renderer（不可信 UI 层）
  React / React Flow / Zustand / 视图与临时交互状态
          ↓ 仅通过白名单 API
Preload（契约与安全边界）
  contextBridge / 参数收敛 / 事件订阅与取消订阅
          ↓ IPC invoke / event
Main（受信任本地业务层）
  文件系统 / SQLite / 索引 / AI / safeStorage / 系统能力
```

### 3.2 强制安全配置

- `contextIsolation: true`；
- `sandbox: true`；
- `nodeIntegration: false`；
- Renderer 不直接使用 Node.js、文件系统、数据库或模型密钥；
- Preload 只暴露明确、窄化、可验证的业务方法；
- 禁止暴露通用 `ipcRenderer.send`、任意文件读取或任意 shell 执行能力；
- IPC 参数进入 Main 后再次校验，不能信任 Renderer 的路径、枚举和对象结构。

### 3.3 推荐目录原则

已有项目不为符合手册而大规模迁移；新建或整理时可采用：

```text
src/
  app/                  # App Shell、启动恢复、全局错误边界
  features/
    canvas/             # 画布、节点、连线、布局、撤销
    assets/             # 导入、状态、资料列表
    knowledge/          # 知识库、检索、引用
    ai/                 # 全局问答、AI 节点、快问、设置 UI
    tasks/              # 任务节点与任务视图
    folder-canvas/      # 文件夹子画布
  components/ui/        # 通用可访问组件
  stores/               # 画布临时状态和用户偏好
  services/desktop/     # window.desktop 类型化适配层
  types/                # 跨功能共享业务类型
  styles/               # 设计变量与全局样式
electron/
  main/                 # 窗口、生命周期、IPC 注册
  preload/              # contextBridge 白名单接口
  services/
    knowledge/          # 资产、解析、索引、检索
    ai/                 # 供应商协议适配与密钥
    workspace/          # 工作区读写、版本与迁移
    filesystem/         # 打开、定位、复制、重命名、废纸篓
tests/
e2e/
```

### 3.4 依赖方向

```text
React 页面/组件
  → Feature Hook / Store Action
  → Renderer desktop service adapter
  → Preload 白名单契约
  → Main IPC handler
  → Domain service
  → SQLite / 文件系统 / AI 服务商
```

页面组件不拼 IPC channel 名，不理解 OpenAI/DeepSeek 特殊字段，也不直接决定磁盘操作。

## 4. 状态与事实来源

### 4.1 状态分层

| 状态类型 | 例子 | 默认位置 |
|---|---|---|
| 视图临时状态 | 菜单开关、框选、当前编辑框、弹窗 | 组件 State |
| 画布会话状态 | 节点位置、连线、选择、视口、撤销栈 | Zustand；持久部分异步写入工作区 |
| 用户偏好 | 主/子画布主题、侧栏偏好 | localStorage 或设置表 |
| 业务事实 | 资产路径、索引状态、chunks、工作区快照 | SQLite / 文件系统，由 Main 管理 |
| 外部事实 | AI 响应、供应商错误、连接状态 | Main AI service 返回的标准结果 |

### 4.2 本项目的事实来源规则

- 文件是否存在、名称和路径，以文件系统实际结果为准；
- 资料及索引状态，以 Main 服务与 SQLite 为准；
- 工作区持久状态，以带版本号的 SQLite 快照为准；
- Renderer 可以立即乐观更新画布，但保存失败必须提示并可恢复；
- localStorage 只作为快速启动缓存或用户偏好，不得无条件覆盖较新的 SQLite 数据；
- AI 请求是否完成，以真实 SDK 返回或重新查询结果为准，不能用动画结束来推断。

### 4.3 双写策略必须明确

PRD 同时描述了 localStorage 即时读写和 SQLite 权威恢复。为避免竞态，开发前应确定：

1. 工作区快照包含 `schemaVersion`、`revision`、`updatedAt`；
2. Renderer 每次变更生成递增 revision；
3. Main 串行化保存，旧 revision 不覆盖新 revision；
4. 启动时优先读取 SQLite；仅在 SQLite 不存在或损坏时使用本地缓存恢复；
5. 保存失败显示非阻塞但持续可见的“尚未保存”状态；
6. 数据结构升级通过显式迁移，不在组件渲染时临时修补。

### 4.4 本地长任务统一状态

索引、重新扫描和 AI 生成至少映射为：

| 统一状态 | 用户含义 | 示例 |
|---|---|---|
| `idle` | 尚未开始 | 文件尚未进入处理队列 |
| `pending` | 已受理等待处理 | 新导入资料 |
| `scanning` | 正在枚举目录 | 文件夹扫描 |
| `processing` | 正在解析或建索引 | PDF 提取、写入 chunks |
| `ready` | 已完成并可使用 | 可参与检索 |
| `unsupported` | 格式暂不支持 | 非支持扩展名 |
| `failed` | 处理失败 | 文件损坏、权限不足 |
| `cancelled` | 用户取消 | 仅在真实支持取消时显示 |
| `stale` | 文件已变化，索引可能过期 | mtime/size 与索引记录不一致 |

AI 任务另需 `submitting`、`running`、`succeeded`、`failed`、`disconnected`。若当前版本不支持取消，就不能把“关闭弹层”写成“取消 AI 任务”。

## 5. 无限画布工程规则

### 5.1 数据模型

- 节点 UI 数据与真实 Asset 数据分离；
- 一个 Asset 可以被不同工作区或位置引用，不能用节点 ID 替代资产 ID；
- Edge 必须有显式语义，视觉样式由语义派生；
- 文件夹收纳属于画布层关系，不等于移动磁盘文件；
- AI 节点的资料范围由图关系计算，不能把缓存的来源列表当永久事实；
- 结论引用保存稳定的资产标识和定位，同时考虑源文件被重命名或删除后的失效展示。

### 5.2 高频交互性能

- 拖拽过程中只更新必要节点，避免每帧序列化整个工作区；
- 持久化采用节流/防抖与 revision 控制；
- 节点组件使用稳定引用和合理 memo，避免全画布重渲染；
- 大型 Markdown、缩略图和文件预览按需加载；
- 迷你地图、搜索高亮和节点尺寸变化需要在真实节点量下压测；
- 不把文件二进制或完整文档文本放进 Zustand；
- 自动布局不得阻塞 Renderer，复杂布局可移至 Worker 或 Main 服务。

### 5.3 画布操作一致性

- 删除节点自动清理关联 Edge；
- 重连 Edge 保持语义，除非产品规则明确要求重新推断；
- 插入 AI 节点是一个原子操作，撤销时一次恢复原连线；
- 收纳、移出、批量整理和批量重命名都应形成可理解的单次撤销；
- 输入框、中文输入法组合态和正文编辑时，画布快捷键不得误触发；
- 撤销只影响画布状态，不应假装撤销已完成的真实磁盘删除。

### 5.4 建议补齐 Redo

当前 PRD 只有 Undo。若后续确认增加 Redo，应使用 `past / present / future` 模型，并明确下列操作是否可重做：

- 纯画布节点和连线操作：可以；
- 磁盘重命名：需单独事务与冲突校验；
- 移到系统废纸篓：默认不可通过普通 Redo/Undo 逆转；
- 资料索引：不进入画布撤销栈。

## 6. 本地资料、解析与索引

### 6.1 导入边界

- 用户显式选择或拖入的路径才进入处理范围；
- 目录递归跳过隐藏项的规则应可配置或至少写入产品说明；
- 文件数量、单文件大小、目录深度和符号链接策略必须明确；
- 避免跟随符号链接形成循环；
- 解析失败不得阻断同批其他文件；
- 目录扫描和解析不能阻塞 Renderer。

### 6.2 解析器契约

每种解析器返回统一结构：

```ts
type ParsedSection = {
  text: string;
  locator: string;
  page?: number;
  heading?: string;
};

type ParseResult = {
  assetId: string;
  sections: ParsedSection[];
  warnings: string[];
};
```

解析器必须区分：不支持、无可提取文本、文件损坏、权限不足、密码保护和未知错误。

### 6.3 增量索引

当前全量重建适合 MVP，进入大资料库阶段后建议：

- 使用路径、大小、mtime 和可选内容 hash 判断是否变化；
- 未变化文件复用 chunks；
- 删除文件清理孤立 chunks 和 FTS 记录；
- 单文件重建使用事务，避免一半新索引、一半旧索引；
- 数据库迁移和索引重建分开管理；
- 建立“索引版本”，分词或 chunk 策略变化时可安全重建。

### 6.4 检索演进路线

第一阶段保留当前关键词 + bigram，优先修正“只取最近 300 chunk 再打分”的召回缺陷：

```text
FTS5 全量候选召回
  → BM25/业务权重排序
  → 资产范围过滤
  → 来源覆盖
  → 截断为可发送给模型的证据集
```

第二阶段再加入本地 embedding 和混合检索：

```text
关键词召回 + 向量召回
  → 结果合并/去重
  → 可选 rerank
  → 来源覆盖
  → 引用证据
```

向量检索引入前必须先确认模型体积、首次下载、离线许可、CPU/内存占用、macOS/Windows 架构兼容、索引迁移和删除机制。

### 6.5 引用可靠性

- 模型只能引用实际发送的证据编号；
- 回答渲染时校验 `[n]` 是否存在；
- 引用保留 chunk ID、asset ID、原定位和必要文本快照；
- 文件移动或重命名后通过 asset ID 更新路径；
- 文件删除后引用仍可显示历史来源名称，但明确标记“原文件已不可用”；
- 后续内嵌预览应通过 locator/page 定位，不用字符串猜测页码。

## 7. AI 服务与供应商适配

### 7.1 统一业务接口

Renderer 不感知 Responses API 或 Chat Completions。Main 内部提供统一接口：

```ts
type KnowledgeAnswerRequest = {
  question: string;
  evidence: Citation[];
  instructions: string;
  providerConfigId: string;
};

type KnowledgeAnswerResult = {
  text: string;
  usedCitationIndexes: number[];
  provider: string;
  model: string;
  requestId?: string;
};
```

供应商适配层负责参数名、错误码、超时、重试和输出文本提取。

### 7.2 提示词层级

建议明确且可追溯：

```text
安全与引用规则（应用内置，不可被资料覆盖）
  > AI 节点独立指令（如有）
  > 用户配置的全局资料问答指令
  > 当前问题和编号证据
```

AI 快问使用完全独立的会话和提示词，不拼接画布节点、文件名、证据或资料摘要。

### 7.3 密钥与配置

- 环境变量或 safeStorage 解密只发生在 Main；
- Renderer 只能读取 `configured`、供应商、模型和脱敏 hint；
- 日志不得记录 Key、完整请求证据或敏感提示词；
- Base URL 必须校验协议与格式，错误信息转为用户可理解文案；
- 保存配置时留空 Key 不覆盖旧 Key；
- 已保存但不可用的模型必须标记，不得静默切换；
- 每个结论建议记录生成时的供应商、模型和时间，便于追溯。

### 7.4 失败与降级

- 无 Key：展示本地检索证据，不发送远程请求；
- 网络失败：保留问题和证据，允许重试；
- 供应商限流：显示可重试时间或清晰建议；
- 部分引用不可用：继续显示可用引用并明确缺失项；
- Markdown 解析失败：降级为纯文本；
- 未知供应商错误：显示安全文案，保留 request ID 供诊断。

### 7.5 隐私提示

“本地优先”不等于“所有内容永不离开本机”。使用云端 AI 时，问题和选中的证据块会发送到用户配置的服务商。产品必须在设置页和首次调用前用普通语言说明发送范围。

## 8. IPC 契约与错误模型

### 8.1 IPC 设计规则

- channel 按业务命名，不按底层函数随意暴露；
- 请求和响应具有 TypeScript 类型及运行时校验；
- 每个事件订阅都返回取消订阅函数；
- 窗口销毁后清理监听器；
- 长任务消息包含 task ID，避免多个扫描任务串线；
- IPC 返回可序列化对象，不返回 Node 原生实例；
- 危险操作在 Main 再确认目标和影响范围。

### 8.2 统一错误结构

```ts
type AppError = {
  code: string;
  userMessage: string;
  retryable: boolean;
  operation: string;
  assetId?: string;
  taskId?: string;
  requestId?: string;
  details?: Record<string, unknown>;
};
```

Renderer 展示 `userMessage`；开发日志可记录脱敏后的 code、operation 和 requestId。不得直接把堆栈、绝对隐私路径、供应商原始报错或密钥展示给用户。

### 8.3 幂等与并发

- 重复导入同一路径应复用或更新 Asset，而不是产生不可控重复记录；
- 同一资产同时重扫时合并或拒绝第二个任务；
- 工作区保存按 revision 串行；
- 文件重命名先在文件系统成功，再更新数据库和画布投影；
- 数据库更新失败时提供补偿或显式不一致提示；
- AI 提交期间禁用重复发送，同一业务请求可附幂等 ID。

## 9. 设计系统与桌面交互

### 9.1 视觉基线

- 主背景：深色 `#090b0f`，浅色 `#f3f5f8`；
- 品牌主色：`#8178ff`；
- 搜索命中：`#ffd34e`；
- 危险操作：`#ff8989` / `#9f3e4d`；
- 节点、按钮、弹窗使用语义 token，不在各组件散落无命名色值；
- 图标统一使用 Lucide，不用表情符号代替正式功能图标。

### 9.2 桌面窗口验收尺寸

至少检查：

- 960×640：最小可用窗口；
- 1280×720：紧凑桌面；
- 1440×900：默认目标；
- 1728×1117 或等价高分屏逻辑尺寸；
- 系统缩放 100%、125%/150%（Windows）和 Retina（macOS）。

### 9.3 可访问性

- 核心操作可用键盘完成；
- 图标按钮有可访问名称和 tooltip；
- 菜单、弹窗有正确焦点约束与返回；
- 状态不仅靠颜色表达；
- 尊重减少动态效果设置，搜索脉动和画布动画可降级；
- 画布之外提供侧栏列表作为可导航替代入口；
- 删除、覆盖和移动到废纸篓使用描述结果的按钮文案。

---

## 10. 文件操作安全红线

1. “移出画布”只删除画布投影，不触碰磁盘文件；
2. “从文件夹画布删除”只影响画布组织，除非按钮明确写“移到系统废纸篓”；
3. 真实删除使用 `shell.trashItem`，不得默认永久删除；
4. 删除前展示准确文件/文件夹名称、数量和索引影响；
5. 重命名校验非法字符、同名冲突、父目录权限和路径穿越；
6. 复制到桌面处理同名、磁盘空间和部分失败；
7. 不对未解析、过宽或来自 Renderer 的任意路径执行递归删除；
8. 磁盘操作成功与数据库同步结果分别记录，任何不一致都要可诊断。

## 11. 测试与真实验收

### 11.1 每阶段最低自动检查

项目应提供等价命令：

```bash
npm run lint
npm run typecheck
npm run test
npm run test:main
npm run build
npm run e2e
```

脚本名称可不同，但 Lint、strict 类型、Renderer 测试、Main 服务测试、生产构建和桌面核心 E2E 不能被“构建成功”替代。

### 11.2 测试分层

| 层级 | 重点 |
|---|---|
| 单元测试 | 图遍历范围、连线语义、状态映射、分块、中文词项、排序、路径规则 |
| 组件测试 | 节点编辑、快捷键保护、加载/空/错、确认对话框、AI 配置 |
| Main 集成测试 | SQLite 事务、FTS、解析器、重命名同步、删除索引、safeStorage 降级 |
| IPC 契约测试 | 参数校验、错误归一化、事件订阅清理、并发任务隔离 |
| Electron E2E | 导入 → 索引 → 连线 → 提问 → 引用 → 保存结论 |
| 人工验收 | 视觉、窗口缩放、键鼠、拖放、系统对话框、Finder/Explorer、废纸篓 |

### 11.3 必测核心闭环

```text
启动应用并恢复工作区
→ 导入一个含 PDF/MD/TXT 的文件夹
→ 看到逐项索引状态
→ 创建知识库并关联资料
→ 创建 AI 节点并连接知识库
→ 提问并获得带有效引用的回答
→ 点击引用打开正确文件
→ 保存为结论节点
→ 创建并关联任务节点
→ 重启应用后节点、连线、引用和布局仍存在
```

### 11.4 异常路径

至少验证：

- 文件被外部删除、移动或改名；
- PDF 无文本层、DOCX 损坏、文件无权限；
- 文件夹很大、包含隐藏文件或符号链接；
- 数据库损坏或迁移失败；
- AI 未配置、超时、限流、断网、返回空文本；
- 保存工作区失败；
- 导入或扫描期间关闭窗口并重新启动；
- 中文输入法下 Enter、Delete、⌘Z 不误触发；
- “移出画布”不会删除磁盘文件；
- “移到废纸篓”影响范围与确认文案一致。

### 11.5 平台矩阵

- macOS：主验收平台，覆盖 Apple Silicon；如支持 Intel 需单列；
- Windows：文件路径、盘符、非法字符、缩放和安装包；
- Linux：若列为正式支持，必须指定发行版和包格式，否则标为实验性；
- 不得只在开发模式验收，至少测试一次打包后的应用。

## 12. 性能与容量基线

开发前应把容量目标写入阶段文档。尚未确认时可使用以下初始验证档位，不作为最终承诺：

| 场景 | 初始验证档位 |
|---|---|

| 单文件 | 10MB / 100MB 文档分档 |

关键指标包括：Renderer 是否掉帧、内存峰值、扫描耗时、检索 P50/P95、数据库体积、首次可交互时间和退出时是否丢保存。

## 14. 分阶段开发建议

### 阶段 0：源码核验与需求冻结

- 获取并完整读取 v0.2.0 源码、`package.json`、锁文件和测试；
- 对照 PRD 标记“真实存在、部分存在、未存在、行为不一致”；
- 确认本轮是修复现有版本、重构，还是从零重建；
- 冻结本阶段范围、数据迁移和验收样本。

### 阶段 1：工程与数据安全基线

- 固化进程边界、IPC 类型、错误模型和工作区 revision；
- 完成数据库备份/迁移策略；
- 补齐 Lint、类型、测试和构建门槛；
- 验证“移出画布”和“废纸篓”的安全边界。

### 阶段 2：第一条真实知识闭环

- 真实导入文件与文件夹；
- 完成解析、索引、检索和引用；
- 完成知识库关系和 AI 节点限定范围问答；
- 保存结论并在重启后恢复。

### 阶段 3：画布与项目工作流

- 完善 7 类节点、4 类连线、文件夹子画布和任务节点；
- 完善批量操作、快捷键、撤销与可能的 Redo；
- 根据确认后的“项目管理”边界增加能力，不根据标题自行扩张。

### 阶段 4：检索与预览升级

- 先修复 FTS 全量召回与增量索引；
- 再评估本地向量模型和混合检索；
- 接入应用内 PDF/Word 预览和引用定位高亮。

### 阶段 5：跨平台与发布质量

- 大数据量性能；
- macOS/Windows 打包验收；
- 签名、公证、更新和迁移；
- 隐私说明、错误诊断和发布清单。

每个阶段都要形成一条可运行、可重复、可验收的业务闭环，不能先堆完页面再统一接真实本地服务。

## 16. 待产品确认事项

以下问题会实质改变后续技术和开发范围：

1. **开发基线**：后续是继续维护 PRD 所述的 v0.2.0 现有源码，还是依据 PRD 从零重建？当前工作目录没有源码，只有 PRD。
2. **“项目管理”的边界**：本期是否只保留任务节点与资料—结论—任务关联，还是要加入多项目、状态、负责人、优先级、截止时间、看板等正式项目管理能力？
3. **下一阶段优先级**：本地向量检索、应用内文档预览、多工作区、Redo 四项中，哪一项是下一阶段第一优先级？
4. **平台承诺**：macOS 是否为首发唯一正式支持平台，Windows/Linux 是本期验收项还是后续兼容目标？
5. **隐私口径**：是否接受“本地索引，但调用云端 AI 时发送问题与最多若干证据块”的模式，还是必须支持完全离线模型？
6. **容量目标**：典型和上限的文件数、单文件大小、画布节点数分别是多少？这会直接影响索引、虚拟化和性能方案。

在这些问题确认前，本手册可作为 V0.1 技术基线，但不应据此启动产品开发。

## 17. 最终原则

1. 先核验现有源码，再决定适配或重构；
2. 以真实用户闭环拆阶段，不以文件数量或页面数量拆阶段；
3. 文件系统、SQLite 和 Main 服务层是本地业务事实来源；
4. Renderer 不持有密钥、不直接访问磁盘、不绕过 IPC 契约；
5. 本地优先必须清楚说明哪些数据仍会发送给云端 AI；
6. 引用必须来自实际证据，并在源文件变化后可识别失效；
7. 画布性能、索引容量、异常恢复和文件删除安全是核心产品功能；
8. 自动检查、打包应用真实验收和异常路径缺一不可；
9. 对待确认项、未完成项和技术债保持透明；
10. 在产品经理确认技术适配和阶段范围前，不开始编码。
